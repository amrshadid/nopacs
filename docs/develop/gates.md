# Gates and outside checks

[Documentation index](../README.md) · [Testing](testing.md) · [Architecture](architecture.md)

The checks a change passes, for people who extend NoPACs. Each is one `make` target. What the tests are and the environment variables they read is in [Testing](testing.md); the rules the checks enforce are in [Architecture](architecture.md#the-rules-and-what-enforces-each).

## The gates before a push

Each gate is one `make` target, run locally before a change is pushed.
`make gates` runs the ones every push needs and never the scale tests:
`check-comments`, `fmt`, `go vet` on 64 bits, linux/386 and windows, `lint`,
and `go test -race` over every package (whose scale tests skip unless
`NOPACS_TEST_SCALE` is set).

| Command | What it checks |
|---|---|
| `make fmt` | `gofmt -s`: fails on any file it would change or cannot parse |
| `make check-comments` | no comment, document or script message refers to a note outside the repository (`scripts/check/comments.py`) |
| `make docs` | writes the generated pages of `docs/reference` (settings, commands, error kinds and codes, event types, metrics, environment variables) from the code that defines them (`internal/testkit/cmd/refdocs`) |
| `make check-docs` | fails, naming the page, when a page of `docs/reference` differs from what `make docs` would write; it starts a throwaway server to read its metrics |
| `make check-doc-links` | every relative link and every anchor in `docs/` and `README.md` resolves (`scripts/check/doc-links.py`) |
| `make vet` | `go vet` on 64 bits, on 32 bits (linux/386) and for Windows |
| `make lint` | golangci-lint with `.golangci.yml`, run for Linux, Windows and macOS so that files built for one system only are linted too, including the rule that `internal/core` imports only the standard library and itself, and from the standard library no database, network, file or system package |
| `make vuln` | govulncheck: no known vulnerability reachable from the code |
| `make test` | `go test -race -count=1 ./...`: always run, never a cached result |
| `make test-scale` | the tenant registry at 1,000 tenants (`TestScaleThousandTenants`), the drivers' tests at scale and the pipeline model under every seed, without the race detector, which that test skips; its time to ready, memory and open files are in the log |
| `make build` | static binaries for linux/amd64, linux/386, linux/arm64, darwin/arm64 and windows/amd64, in `bin/` |
| `make size` | the size of each binary `make build` left, as a table |
| `make proto-lint` | `buf lint` on the API contract in `api/proto` |
| `make proto-breaking` | `buf breaking` against the commit where `HEAD` and `PROTO_BASE` (default `origin/develop`) meet; skipped, saying so, when that commit has no proto files; a package renamed in `api/renamed.txt` is read under its new name |
| `make proto-check` | regenerates the Go code and fails if it differs from the committed `gen/` |
| `make check` | `check-comments`, `fmt`, `vet`, `lint`, `vuln`, `test`, `build`, `size` and the proto checks; not `make test-scale`, in that order; the scale tests run on their own, on a machine meant for them |

## The API contract

The API contract is protobuf, package `nopacs.v1`, in `api/proto`; `make
proto` regenerates the Go code in `gen/`, which is committed and never edited
by hand. `make proto-python` compiles the same files with Python's
grpcio-tools as a second toolchain (it needs a `PYTHON` with
`scripts/requirements/proto.txt` installed, so it is not in `make check`).

## Outside checks

These checks need more than Go, so `make check` leaves them out; each runs on
its own, against a tool that is not NoPACs:

| Command | What it checks |
|---|---|
| `make check-seal PYTHON=python3` | the format of a sealed secret against another implementation: `scripts/check/seal.py`, with Python's `cryptography` package, opens a value Go sealed, and Go opens a value Python sealed. `PYTHON` names an interpreter that has the package; `pip install --require-hashes -r scripts/requirements/check-seal.txt` installs it at the versions CI uses. An empty `PYTHON` or a missing interpreter fails |
| `make fuzz` | each fuzz target for `FUZZTIME` (10 seconds unless given) |
| `make test-386` | the tests as linux/386 binaries, which a Linux x86-64 machine runs natively (macOS cannot) |
| `make check-server PYTHON=... GRPCURL=grpcurl` | the server against three clients that are not NoPACs: `scripts/check/server.sh` runs a real server with stand-in handlers, then curl, grpcurl and Python's grpcio (`scripts/requirements/check-server.txt`) each get the same refusal for no key, a malformed key, an unknown key and a key with no grant, and success for an admin key over TLS and for the local operator on the socket; `/metrics` is parsed by the Prometheus Python client; SIGTERM must exit 0 |
| `make check-master-sqlite SQLITE3=sqlite3` | the SQLite master database against SQLite's own `sqlite3` tool: `scripts/check/master-sqlite.sh` has the driver write a sample installation, then lists its tables and rows, runs `PRAGMA integrity_check` and `PRAGMA foreign_key_check`, reads times and audit details with SQLite's functions, and searches a dump for the sample key's secret (absent) and its hash (present). The master's tables are `STRICT`, so the `sqlite3` tool must be 3.37 or later to open the database at all |
| `make check-json` | every command with `--json` against the in-process server, each output parsed by Python's `json` module (`scripts/check/cli-json.py`, standard library only) and checked for `schemaVersion` |
| `make check-completion` | the bash completion script the binary writes, parsed by `bash -n` |
| `make check-tenant-sqlite SQLITE3=sqlite3` | a tenant's SQLite database against the `sqlite3` tool: `scripts/check/tenant-sqlite.sh` has the tenant registry create a tenant on SQLite in a fresh data directory and write a sample into it, then checks that its file is `<data-dir>/tenants/<name>.db` and private, lists its tables and rows, runs `PRAGMA integrity_check`, and reads the tenant's row and its state change from the master |
| `make check-tui` | the interactive program, as built, run under a pseudo-terminal by Python's `pty` module against the in-process fake server (`scripts/check/tui.py`, standard library only): keys pressed, the screen read, quit, SIGTERM and SIGINT mid-session, and the terminal checked to be restored. Linux and macOS only |
| `make check-master-postgres` | the Postgres master database against `psql` and `pg_dump`: `scripts/check/master-postgres.sh` has the driver write a sample installation into a schema of the database `NOPACS_TEST_POSTGRES` names (a `postgres://` URL), then lists its tables and rows, checks every constraint and foreign key, reads times and audit details with Postgres's functions, and searches a `pg_dump` for the sample key's secret (absent) and its hash (present). `PSQL=` and `PG_DUMP=` name the commands, which may run in a container; then `PSQL_URL=` gives the database's address as the container sees it. The Postgres tests of `go test` use the same variable and skip without it; `NOPACS_REQUIRE_POSTGRES=1` makes a missing address a failure, as CI sets it |
| `make check-tenant-postgres` | a tenant on Postgres against `psql` and `pg_dump`: `scripts/check/tenant-postgres.sh` has the registry create a tenant on Postgres, in a schema of the database `NOPACS_TEST_POSTGRES` names, with a Postgres master in another, writes the tenant suite's sample, then lists the tables and rows, checks every constraint and index, reads times and audit details, reads the tenant's row and state change from the master, checks the schema records the tenant's id, and searches both dumps for the login's password (absent) |
| `make prove PYTHON=... GRPCURL=grpcurl` | the proof of this version, from outside: `scripts/prove/run.sh` builds every target as `make build` does, then runs the real binary: `init` and `serve` on the local socket and TLS; the first key made on the socket; every method of the contract refused without a key; tenants on SQLite and on Postgres (in a container it starts, or the one `NOPACS_PROVE_PG_CONTAINER` names); no key, a malformed, unknown, wrong, expired and revoked key, and a key with no grant tried with grpcurl, Python's grpcio and curl, the answers compared byte for byte; secrets searched for in the databases' dumps, every file, the logs and the audit log; the server with another key file; Postgres stopped and started under a running server; the server killed with signal 9 during tenant creation at least 20 times; every request reconciled with the audit log; a second server and another operating system user refused; `--json` and the interactive program; the size of each binary. One line per check and a table at the end; a check it cannot run here (a second user without sudo) is skipped and says so, and `NOPACS_PROVE_STRICT=1` (CI) fails on any skip. It needs docker and leaves nothing behind |
| `make prove-reception PYTHON=... DCMTK=dir` | the reception, from outside: `scripts/prove/reception.py` serves the real binary, sends public studies with dcmtk's storescu and pynetdicom, and checks with dcmdump, pydicom, hashlib and sqlite3 what was archived, quarantined and counted: byte for byte, manifests, duplicates, a corrected and a broken file, strangers refused, kills by signal 9 while receiving, in the quiet period and while archiving, a nearly full storage, a released file, the status and the event stream. `PROVE_S3` adds a tenant on an S3 bucket read back by GETs the proof signs itself, and `PROVE_POSTGRES` with `PROVE_PSQL` a tenant on Postgres read by psql (`scripts/requirements/prove-reception.txt`) |
| `make prove-deid PYTHON=... DCMTK=dir PYDICOM_CORPUS=dir` | de-identification, from outside: `scripts/prove/deid.py` serves the real binary and sends public corpus files and files it builds, with names, dates, identifiers, private elements, JPEG and JPEG 2000 comments and burned-in pixels planted, through de-identifying receivers; pydicom, dcmdump, dcmdjpeg, sqlite3 and a byte search find no planted value in any archived file, manifest, database or log. Every way a file is held and its release, pixel rules, routing, value patterns, the forward lookup and lookup import, `profile try --local`, `release --profile`, `deid.memory`, names written decomposed, and kills by signal 9 while archiving. It runs several minutes: `PROVE_DEID_ONLY=group,...` runs a part; `PROVE_DEID_ORTHANC=1` adds a session read back from an empty Orthanc (`scripts/requirements/prove-reception.txt` and `prove-deid.txt`) |
| `make prove-import PYTHON=... PYDICOM_CORPUS=dir` | importing a directory, from outside: `scripts/prove/importing.py` serves the real binary and imports trees of two layouts built from the public corpus, with a link, two names of one file, non-DICOM files, a folder wider than `import.max-dir-entries`, a path over 2048 bytes, a folder named `ct:9`, a file outside the layout, an unmapped session, a file over the largest file and an instance in two folders. `job show`, `job files` and `job units` give the counts, both identities and every skip with its code; pydicom and SHA-256 show the archive equal to the tree with the labels the layout and map give; the tree is unchanged; a second run holds everything; roots in the archive's own directories are refused; a reader sees no path; a de-identifying receiver archives no value of the tree and an SR's references resolve to remapped instances of the same tenant; a server killed with signal 9 midway ends with the counts of an uninterrupted run. | `make prove-whole PYTHON=... DCMTK=dir PYDICOM_CORPUS=dir` | keeping the archive whole, from outside: `scripts/prove/whole.py` serves the real binary, archives public corpus studies with dcmtk's storescu (as received and de-identified) and checks with hashlib, os.walk, sqlite3, pydicom, curl, dcmtk and `catalog_dump.py`/`backup_open.py`. ## Tools, and where the checks run

`make lint` and `make vuln` install the pinned golangci-lint and govulncheck
into `bin/tools/` the first time, and the proto targets do the same for buf,
protoc-gen-go and protoc-gen-connect-go; nothing is installed outside the
checkout. buf is the release binary for Linux or macOS (x86-64 or ARM),
installed only if its SHA-256 matches the one in `scripts/tools/buf.sha256`.
`make` needs a Unix shell; on Windows run `go vet ./...` and `go test ./...`
directly.

The workflows in `.github/workflows` describe the same gates on Linux with Go
1.26 and 1.27, on Windows and on macOS, with Postgres 16 and 18 and two S3
servers (Silo and RustFS); they are not run on each push, and the gates above
are run locally instead. `make test-postgres` and `make test-s3` run the
database drivers, the S3 driver and the reception end to end against those
services, and fail if the service they need is missing. Without one, the
tests that need it skip and say so in the log.
