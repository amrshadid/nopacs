# Error kinds and codes

Every failure the API answers has a kind. The kind decides the API code the server answers with, and the
exit status of the `nopacs` command that received it. A caller reads the code; a script reads the exit status.
What each method may answer, and the reasons some kinds carry in an error detail, are in the comments of the
contract in `api/proto/nopacs/v1`.

## Kinds

| Kind | API code | HTTP status | Exit status | What it means |
|---|---|---|---|---|
| internal | `INTERNAL` | 500 | 1 | A failure of the archive itself, or a cause the caller must not be told about. The message says nothing of the cause; it is in the server's log under the request id. |
| invalid | `INVALID_ARGUMENT` | 400 | 2 | The request is wrong as written: a malformed name, a missing argument, a value out of range. Sending it again unchanged fails again. |
| unauthenticated | `UNAUTHENTICATED` | 401 | 3 | No key, or a key that is malformed, unknown, expired, revoked or suspended. All of these get one answer, so a caller cannot tell which. |
| denied | `PERMISSION_DENIED` | 403 | 3 | The key is good but holds no grant with the role the method needs. A tenant that does not exist is answered the same way to a caller who may not list tenants. |
| not found | `NOT_FOUND` | 404 | 4 | The thing named does not exist, among the things the caller may see. |
| conflict | `ALREADY_EXISTS` | 409 | 1 | The change would collide with what exists, such as a second tenant with the same name. |
| unavailable | `UNAVAILABLE` | 503 | 1 | A database or a storage the request needs does not answer, or a tenant is not ready. Sending it again later may succeed. |
| precondition | `FAILED_PRECONDITION` | 400 | 5 | What the request names is in a state that forbids the change: a storage that still holds files, a port the installation has not allotted. It fails again until that state changes. |
| out of range | `OUT_OF_RANGE` | 400 | 6 | A position that can no longer be answered, such as an event cursor older than the oldest event kept. Start over from a status. |
| exhausted | `RESOURCE_EXHAUSTED` | 429 | 7 | A bound of the server is reached: a message over the size limit, too many streams or reads open. Send less, or later. |
| data loss | `DATA_LOSS` | 500 | 1 | Archived data is missing or damaged: a file gone from its storage, or bytes that do not match the SHA-256 recorded when they were archived. The message names the scan to mend. |

## Every code

A client may receive any of the sixteen codes of the protocol. This is the kind each one is taken for, and so the exit
status of `nopacs` for it. A code no kind carries is a failure of the call (exit status 1): it is never shown as the
caller's mistake.

| API code | HTTP status | Taken for the kind | Exit status |
|---|---|---|---|
| `CANCELED` | 499 | unavailable | 1 |
| `UNKNOWN` | 500 | internal | 1 |
| `INVALID_ARGUMENT` | 400 | invalid | 2 |
| `DEADLINE_EXCEEDED` | 504 | unavailable | 1 |
| `NOT_FOUND` | 404 | not found | 4 |
| `ALREADY_EXISTS` | 409 | conflict | 1 |
| `PERMISSION_DENIED` | 403 | denied | 3 |
| `RESOURCE_EXHAUSTED` | 429 | exhausted | 7 |
| `FAILED_PRECONDITION` | 400 | precondition | 5 |
| `ABORTED` | 409 | internal | 1 |
| `OUT_OF_RANGE` | 400 | out of range | 6 |
| `UNIMPLEMENTED` | 501 | internal | 1 |
| `INTERNAL` | 500 | internal | 1 |
| `UNAVAILABLE` | 503 | unavailable | 1 |
| `DATA_LOSS` | 500 | data loss | 1 |
| `UNAUTHENTICATED` | 401 | unauthenticated | 3 |

## Reasons

Every error the server answers carries a `google.rpc.ErrorInfo` detail with the domain `nopacs` and a
reason, a fixed word a program branches on. A failure that is one of the cases below carries that case's reason,
which also begins its message, and the metadata the case names when it knows them. Any other failure carries
its code's general reason, the code's name above (`NOT_FOUND`, `UNAVAILABLE`, ...), which says no more than the
code. A reason a client does not know is one added later: it treats it as its code alone. How to read them, and
the retry delays some carry: [Reasons and retry delays](../api/errors.md).

| Reason | Kind | API code | Metadata | When |
|---|---|---|---|---|
| `TENANT_MOVED` | precondition | `FAILED_PRECONDITION` | none | A change to a tenant an export handed to another installation; it is read only here. |
| `TENANT_FENCED` | precondition | `FAILED_PRECONDITION` | none | A change to, or a read of the data of, a tenant whose storages name another installation or a later generation; it serves no data here. |
| `HELD` | precondition | `FAILED_PRECONDITION` | `hold` | A delete of data a hold covers. |
| `RETENTION_MINIMUM` | precondition | `FAILED_PRECONDITION` | `keep_until` | A person's delete of data a retention rule keeps at least until a time to come. |
| `RELABELED` | not found | `NOT_FOUND` | `correction`, `to_label` | A subject, session or scan asked for by a label a relabel moved, asked by a caller who may read the tenant's corrections. |
| `TENANT_RESTORING` | unavailable | `UNAVAILABLE` | none | The tenant is being reconciled after a restore; retry with a backoff. |
| `NOT_ONLINE` | unavailable | `UNAVAILABLE` | `recall_state` | The storage holds the object in a tier it cannot read at once, and no copy in step on another storage is online. A retry delay comes only while a recall runs. |
| `STORAGE_SWITCHING` | unavailable | `UNAVAILABLE` | none | A write to a storage being switched to its replica waits for the swap; it carries a retry delay. |
| `CURSOR_EXPIRED` | out of range | `OUT_OF_RANGE` | none | An event cursor before the oldest event kept; start over from a status. |
| `EVENT_HISTORY_CHANGED` | out of range | `OUT_OF_RANGE` | none | An event cursor of another history of the tenant's feed, or past its newest event; start over from a status. |
