# Command reference

Every command of the two programs, with the flags each takes. `nopacs <command> --help` prints the same,
with examples. Each program also has the commands `help` and `completion`, which the command library adds:
`completion bash` (also `zsh`, `fish` and `powershell`) writes the shell's completion script.

- [nopacs](#nopacs), the command line: a client of the API that links no database or storage driver.
- [nopacs-server](#nopacs-server): the server, and the commands that touch the data directory while it is stopped.

## nopacs

nopacs operates a NoPACs installation through its API.

By default it reaches the server on the local socket in the data directory
(--data-dir, or NOPACS_DATA_DIR), as the operating system user that runs the
server, with no key. With --server (or NOPACS_SERVER) it reaches a server on
the network over TLS, with the key read from NOPACS_KEY or from the file named
by --key-file. A key is never an argument: arguments are visible to every user
of the machine and are kept in shell history. A key that works only with a TLS
client certificate is used with --tls-client-cert and --tls-client-key. A
context (nopacs context --help) saves a server with its key file and TLS files
under a name: --context NAME, NOPACS_CONTEXT, or the current context.

Output is a table for a person. With --json it is one JSON document with a
"schemaVersion" field, for a program. An error is one line on standard error;
with --json that line is a JSON object whose "reason" is a fixed word.

Exit codes: 0 done, 1 failed, 2 wrong usage, 3 refused (not authenticated, or
not allowed), 4 not found, 5 a state that forbids the change, 6 a position
that can no longer be answered, 7 a bound of the server reached.

Flags every command takes:

| Flag | Type | Default | What it does |
|---|---|---|---|
| `--ca-file` | string |  | path of a PEM file of certificate authorities to trust for --server, instead of the system's, for a private authority (default: NOPACS_CA_FILE); it has no effect on the local socket |
| `--context` | string |  | name of a saved context, a server with its key and files (default: NOPACS_CONTEXT, then the current context; see nopacs context --help) |
| `--data-dir` | string |  | the installation's data directory; the server is reached on its local socket, run/nopacs.sock (default: NOPACS_DATA_DIR) |
| `--json` | bool |  | write one JSON document with schemaVersion instead of a table |
| `--key-file` | string |  | path of a file holding the key to send with --server (default: the NOPACS_KEY variable); the key itself is never an argument |
| `--server` | string |  | address of a server on the network, https://host:port (http:// only for a loopback host); needs a key (default: NOPACS_SERVER) |
| `--timeout` | duration | `30s` | how long one call to the server may take |
| `--tls-client-cert` | string |  | path of a PEM file of a TLS client certificate to present to --server, for a key that works only with it; needs --tls-client-key (default: NOPACS_TLS_CLIENT_CERT) |
| `--tls-client-key` | string |  | path of the PEM file of that certificate's private key, private to you (default: NOPACS_TLS_CLIENT_KEY) |

### `nopacs audit`

Read, verify and export the audit log

Usage: `nopacs audit`

#### `nopacs audit checkpoints`

List an audit log's signed checkpoints, newest first

Usage: `nopacs audit checkpoints [--tenant NAME] [flags]`

| Flag | Type | Default | What it does |
|---|---|---|---|
| `--all` | bool |  | fetch every item, page after page |
| `--limit` | int | `100` | the most items to fetch; when more exist the command says so |
| `--tenant` | string |  | list this tenant's checkpoints (default: the installation's) |

#### `nopacs audit export`

Export an audit log's sealed entries and checkpoints as JSON lines

Usage: `nopacs audit export [--tenant NAME] [--from SEQ] [--to SEQ] [--out FILE] [flags]`

| Flag | Type | Default | What it does |
|---|---|---|---|
| `--from` | int64 |  | the first seq to export; moved back to the start of the checkpoint that covers it (default: the first kept) |
| `--out` | string |  | write the export to this file, never replacing one (default: standard output) |
| `--tenant` | string |  | export this tenant's log (default: the installation's log) |
| `--to` | int64 |  | the last seq to export; the export ends with the checkpoint that covers it (default: the last sealed entry) |

#### `nopacs audit list`

List audit entries, newest first

Usage: `nopacs audit list [--tenant NAME] [--key-id ID] [--outcome done|refused|failed] [--since TIME] [--until TIME] [flags]`

| Flag | Type | Default | What it does |
|---|---|---|---|
| `--all` | bool |  | fetch every item, page after page |
| `--key-id` | string |  | only entries of requests that carried the key with this id (the key's public id, never the key itself) |
| `--limit` | int | `100` | the most items to fetch; when more exist the command says so |
| `--outcome` | string |  | only entries with this outcome: done, refused or failed |
| `--since` | string |  | only entries at or after this time: a date, a time with its offset, or an age such as 24h |
| `--tenant` | string |  | read this tenant's log (default: the installation's log) |
| `--until` | string |  | only entries before this time, written like --since |

#### `nopacs audit public-key`

| Flag | Type | Default | What it does |
|---|---|---|---|
| `--installation` | string |  | the installation whose key it is, once a tenant import brings another's (default: this one) |

#### `nopacs audit verify`

Recompute an audit log's hash chain and check its signed checkpoints

Usage: `nopacs audit verify [--tenant NAME] [--from SEQ] [--to SEQ] [--expect-seq N] [--expect-digest HEX] [flags]`

| Flag | Type | Default | What it does |
|---|---|---|---|
| `--expect-digest` | string |  | the digest of a checkpoint known to be in the log, in hexadecimal, kept outside the installation |
| `--expect-seq` | int64 |  | a seq the log is known to have reached, kept outside the installation |
| `--from` | int64 |  | the first seq to verify; moved back to the start of the checkpoint that covers it (default: the first) |
| `--tenant` | string |  | verify this tenant's log (default: the installation's log) |
| `--to` | int64 |  | the last seq to verify (default: the last sealed entry) |

## nopacs-server

nopacs-server runs a NoPACs installation: init makes the data directory, the
key file and the master database; serve runs the server; backup, tenant import
and the rest touch the data directory with the server stopped. Everything else
is done through the server's API with the nopacs command line.

The data directory is --data-dir, or NOPACS_DATA_DIR.

Exit codes: 0 done, 1 failed, 2 wrong usage, 3 refused, 4 not found, 5 a state
that forbids the change.

Flags every command takes:

| Flag | Type | Default | What it does |
|---|---|---|---|
| `--data-dir` | string |  | the installation's data directory (default: NOPACS_DATA_DIR) |

### `nopacs-server backup`

#### `nopacs-server backup create`

#### `nopacs-server backup restore`

Restore a backup into an empty data directory, or reconcile databases a site restored itself

Usage: `nopacs-server backup restore FILE | --reconcile-only [flags]`
